# 📘 Виды памяти в C

Понимание того, как и где хранятся данные, — фундамент для написания эффективных и надёжных программ на C. Память в C можно классифицировать по нескольким критериям: время жизни, способ выделения, местоположение и назначение. В этом конспекте мы разберём все основные виды памяти, их характеристики и примеры использования.

---

## Модель памяти программы

Когда программа запускается, операционная система выделяет для неё виртуальное адресное пространство, которое делится на сегменты:

- **Сегмент кода (текст программы)** — содержит машинные инструкции, обычно только для чтения.
- **Сегмент данных (data)** — хранит инициализированные глобальные и статические переменные.
- **Сегмент BSS** — хранит неинициализированные глобальные и статические переменные; обнуляется при загрузке.
- **Куча (heap)** — область для динамического выделения памяти во время выполнения.
- **Стек (stack)** — область для локальных переменных и служебной информации (кадры вызовов функций).

С точки зрения программиста важнее **время жизни** объектов:

| Вид памяти | Время жизни | Способ выделения |
|---|---|---|
| Статическая | Всё время работы программы | На этапе компиляции/загрузки |
| Автоматическая (стек) | В пределах блока (функции) | При входе в блок, освобождается при выходе |
| Динамическая (куча) | Управляется программистом (до явного `free`) | `malloc`/`calloc`/`realloc` |
| Регистровая | Время выполнения инструкции | Компилятор может размещать переменные в регистрах процессора |

Рассмотрим каждый вид подробнее.

## Статическая память (Static Storage Duration)

Переменные со статическим временем жизни создаются до запуска `main()` и уничтожаются после завершения программы. Они хранятся в сегментах `data` и `bss` и не зависят от стека или кучи.

К ним относятся:

- **Глобальные переменные** (объявлены вне любой функции).
- **Статические локальные переменные** (объявлены внутри функции с ключевым словом `static`).
- **Статические глобальные переменные** (глобальные с ключевым словом `static` — видны только в пределах одного `.c` файла).
- **Строковые литералы и константы** — обычно в read-only сегменте.

```c
#include <stdio.h>

int global_var = 10;            // статическая память (глобальная, инициализированная)
int global_uninit;              // статическая память (BSS, обнулится)
static int file_local = 42;     // видна только в этом .c файле

void foo(void) {
    static int static_local = 0; // инициализируется один раз
    static_local++;
    printf("%d ", static_local);
}

int main(void) {
    foo(); // 1
    foo(); // 2
    foo(); // 3
    return 0;
}
```

**Особенности:**

- Инициализация происходит до `main` (или при первом проходе для локальных статических).
- Значение сохраняется между вызовами.
- Память выделяется один раз, адрес фиксирован.
- Неинициализированные глобальные и статические переменные обнуляются (сегмент BSS).
- Инициализированные — попадают в сегмент `data`.

**Где использовать:**

- Счётчики вызовов функций.
- Глобальные настройки и таблицы.
- Константные данные, которые должны жить всё время работы программы.
- Буферы для функций, возвращающих указатель (с осторожностью — не потокобезопасно).

## Автоматическая память (Стек) — Automatic Storage Duration

Автоматические переменные создаются при входе в блок (например, функцию) и уничтожаются при выходе из него. Они размещаются в области стека, который растёт и уменьшается динамически.

```c
void example(void) {
    int local_var = 5;        // автоматическая память
    double arr[100];          // массив на стеке
    char buf[256];
    // ... при выходе из функции память освобождается
}
```

**Характеристики стека:**

- Размер ограничен (обычно несколько мегабайт).
- Выделение и освобождение очень быстрые (простое перемещение указателя стека).
- Не требует ручного управления.
- Данные обычно хорошо кэшируются.
- **Нельзя возвращать указатель на локальную переменную** — она разрушится.

```c
int *bad(void) {
    int x = 10;
    return &x; // опасно: x удалится после выхода
}
```

**Где использовать:**

- Почти все локальные переменные.
- Небольшие массивы с известным на этапе компиляции размером.
- Временные объекты и буферы.

**VLA (Variable Length Arrays, C99)**

Массив переменной длины — размер задаётся во время выполнения, но память всё равно выделяется на стеке:

```c
void f(size_t n) {
    int arr[n]; // VLA, размер n известен только в runtime
    // ...
}
```

Ограничения:

- Нельзя использовать в глобальной области.
- Нельзя инициализировать.
- Может привести к переполнению стека при больших `n`.
- В C11 стал опциональным (проверяется макросом `__STDC_NO_VLA__`).
- В C23 снова обязателен, но с оговорками.

Для больших динамических массивов лучше использовать `malloc`.

## Динамическая память (Куча) — Dynamic Storage Duration

Память в куче выделяется и освобождается явно во время выполнения с помощью функций стандартной библиотеки. Она не привязана к области видимости — объект живёт до тех пор, пока не будет вызван `free`.

### Основные функции

```c
#include <stdlib.h>

void *malloc(size_t size);              // выделяет size байт, не инициализирует
void *calloc(size_t n, size_t size);    // выделяет n*size байт, обнуляет
void *realloc(void *ptr, size_t size);  // меняет размер блока
void free(void *ptr);                   // освобождает память
```

**Пример:**

```c
#include <stdlib.h>
#include <string.h>

int *p = malloc(sizeof(int));    // выделение памяти
if (p == NULL) {
    // обработка ошибки
}
*p = 42;
free(p);                         // освобождение
p = NULL;                        // защита от dangling pointer

// массив из 100 int
int *arr = calloc(100, sizeof(int)); // все элементы = 0
// ...
arr = realloc(arr, 200 * sizeof(int)); // расширение до 200
free(arr);
arr = NULL;
```

**Особенности кучи:**

- Размер ограничен доступной виртуальной памятью (обычно много).
- Выделение и освобождение медленнее стека (работа аллокатора, поиск свободного блока).
- Возможна фрагментация памяти.
- Требует явного контроля — риск утечек, двойного `free`, висячих указателей.
- Объекты в куче могут жить дольше, чем создавшая их функция.
- `malloc` возвращает `void *`, который **неявно** приводится к любому указательному типу в C (в отличие от C++, где нужно явное приведение).

**Где использовать:**

- Когда размер данных неизвестен на этапе компиляции.
- Когда объект должен пережить область видимости функции.
- Для больших массивов и структур.
- Для динамических структур данных: связные списки, деревья, хеш-таблицы.

### Типичные ошибки при работе с кучей

```c
// 1. Утечка памяти
int *p = malloc(sizeof(int));
p = NULL; // потеряли адрес, free уже не вызвать

// 2. Двойное освобождение
int *q = malloc(sizeof(int));
free(q);
free(q); // UB

// 3. Использование после free
int *r = malloc(sizeof(int));
free(r);
*r = 5; // UB

// 4. Непроверенный malloc
int *s = malloc(sizeof(int));
*s = 5; // если s == NULL — падение

// 5. free не от malloc
int x = 5;
free(&x); // UB

// 6. Неверный sizeof
int *t = malloc(10); // хотели 10 int, а выделили 10 байт
```

**Правила:**

- Всегда проверяйте результат `malloc`/`calloc`/`realloc` на `NULL`.
- После `free` обнуляйте указатель: `p = NULL`.
- Освобождайте ровно то, что выделили.
- Не освобождайте одну и ту же память дважды.
- Помните: `sizeof(ptr)` — это размер указателя, а не массива.
- Для массива `int` из `n` элементов: `malloc(n * sizeof(int))`.

### `realloc` — тонкости

```c
int *arr = malloc(10 * sizeof(int));
int *tmp = realloc(arr, 20 * sizeof(int));
if (tmp == NULL) {
    // arr всё ещё валиден, можно продолжать работу
    free(arr);
    return -1;
}
arr = tmp; // только теперь перезаписываем
```

Нельзя писать `arr = realloc(arr, ...)` — при ошибке потеряете исходный указатель и получите утечку.

`realloc(NULL, size)` эквивалентен `malloc(size)`.
`realloc(ptr, 0)` — поведение зависит от реализации; обычно освобождает память, но может вернуть `NULL` или уникальный указатель.

## Регистровая память (Register)

Компилятор может оптимизировать код, размещая часто используемые переменные непосредственно в регистрах процессора.

```c
for (int i = 0; i < 1000000; ++i) {
    // компилятор может держать i в регистре
}
```

**Особенности:**

- Программист не управляет размещением в регистрах.
- Ключевое слово `register` существует, но носит лишь рекомендательный характер.
- Переменная с `register` **не имеет адреса** — нельзя применить `&`.
- В современном коде `register` практически не используется; компиляторы сами решают, что оптимизировать.

```c
register int counter = 0;
// int *p = &counter; // ошибка: нельзя взять адрес
```

## Память для констант и литералов

Строковые литералы и константные данные обычно помещаются в отдельный read-only сегмент. Попытка изменить такой литерал — неопределённое поведение.

```c
const char *str = "Hello";   // "Hello" лежит в read-only памяти
// str[0] = 'h';             // UB, часто краш

char arr[] = "Hello";        // копия в стек/статическую память
arr[0] = 'h';                // OK
```

**Разница:**

- `const char *str = "Hello";` — указатель на read-only литерал.
- `char arr[] = "Hello";` — массив, скопированный из литерала, изменяемый.

**Ключевое слово `const`:**

- Означает «только для чтения» через данный указатель.
- Не гарантирует, что объект реально в read-only памяти.
- Компилятор может поместить `const`-объекты в read-only сегмент.

```c
const int x = 10;        // может быть в read-only или оптимизировано
const int *p = &x;       // указатель на константу
int * const q = &y;      // константный указатель
const int * const r = &x; // и то, и другое
```

## Нестандартные и POSIX-функции

### `alloca`

Нестандартная (но широко поддерживаемая) функция для выделения памяти **на стеке**:

```c
#include <alloca.h> // или <malloc.h> в зависимости от системы

void f(size_t n) {
    char *buf = alloca(n);
    // buf автоматически освобождается при выходе из f
}
```

- Плюсы: быстро, автоматически освобождается.
- Минусы: нестандартна, небезопасна при больших `n`, UB при использовании после выхода из функции.

### `strdup` (POSIX)

```c
char *s = strdup("hello"); // выделяет память и копирует строку
// ...
free(s);
```

Требует `#define _POSIX_C_SOURCE 200809L` перед `#include <string.h>`.

### `posix_memalign` / `aligned_alloc` (C11)

Для выделения памяти с заданным выравниванием:

```c
void *ptr;
if (posix_memalign(&ptr, 64, 1024) != 0) {
    // ошибка
}
// ...
free(ptr);
```

```c
void *p = aligned_alloc(64, 1024); // C11
free(p);
```

## Сравнение памяти стека и кучи

| Критерий | Стек | Куча |
|---|---|---|
| Скорость выделения | Очень быстрая (O(1)) | Медленнее (поиск блока, работа аллокатора) |
| Размер | Ограничен (обычно МБ) | Ограничен только памятью ОС (ГБ) |
| Время жизни | Автоматическое (блок) | Ручное (до `free`) |
| Управление | Автоматическое компилятором | Явное программистом |
| Фрагментация | Нет | Возможна |
| Ошибки | Переполнение стека | Утечки, двойное `free`, висячие указатели |
| Где данные | Обычно в кэше (быстрый доступ) | Может быть в ОЗУ, промахи кэша |
| Размер объекта | Должен быть известен на этапе компиляции (кроме VLA) | Может быть динамическим |
| Возврат указателя | Нельзя (dangling) | Можно (живёт до `free`) |

## Важные нюансы C

- **Нет конструкторов и деструкторов.** `malloc` и `free` только резервируют и освобождают байты; инициализация — на программисте.
- **Нет умных указателей.** Управление памятью полностью ручное.
- **Нет RAII.** Нельзя привязать освобождение ресурса к времени жизни объекта.
- **`malloc` возвращает `void *`.** В C неявно приводится к любому указательному типу. Явное приведение не обязательно, но иногда используется для совместимости с C++.
- **`sizeof` массива vs указателя.** Внутри функции `sizeof(arr)` для параметра-массива даст размер указателя, а не массива.
- **Выравнивание (alignment).** `malloc` возвращает память, выровненную под любой фундаментальный тип. Для более строгих требований — `aligned_alloc` или `posix_memalign`.
- **Строгое алиасинг-правило.** Нельзя обращаться к объекту через указатель несовместимого типа (кроме `char *`), иначе UB.
- **Переполнение знаковых целых.** В C — UB, компилятор может оптимизировать в предположении, что переполнения не бывает.

## Практические рекомендации

1. **По умолчанию используйте стек** — он быстр и безопасен.
2. **Если объект должен жить дольше функции или его размер неизвестен — используйте кучу.**
3. **Всегда проверяйте `malloc`/`calloc`/`realloc` на `NULL`.**
4. **После `free` обнуляйте указатель.**
5. **Освобождайте ровно то, что выделили.**
6. **Не создавайте огромные локальные массивы на стеке** — риск переполнения.
7. **Для больших массивов используйте `malloc` или `realloc`.**
8. **Не возвращайте указатели на локальные переменные.**
9. **Помните о фрагментации** — при интенсивном выделении/освобождении рассмотрите пулы памяти.
10. **Используйте инструменты**: `valgrind`, AddressSanitizer (`-fsanitize=address`), UndefinedBehaviorSanitizer (`-fsanitize=undefined`) для отлова ошибок работы с памятью.
11. **Инициализируйте память после `malloc`**, если не используете `calloc`.
12. **При работе со структурами** не забывайте, что `free` не обнуляет поля и не вызывает никаких функций очистки — если внутри были `malloc`-указатели, освобождайте их отдельно.

## Мини-шпаргалка

```c
// Стек
int x = 5;                     // автоматическая
int arr[100];                  // массив на стеке
void f(void) {
    int local = 1;             // живёт до конца f
}

// Статическая
int global;                    // BSS, обнулена
int g = 5;                     // data, инициализирована
void f(void) {
    static int counter = 0;    // инициализируется один раз
    counter++;
}

// Куча
int *p = malloc(sizeof(int));
*p = 42;
free(p);
p = NULL;

int *a = calloc(10, sizeof(int));    // 10 нулей
a = realloc(a, 20 * sizeof(int));    // расширение
free(a);
a = NULL;

// read-only
const char *s = "hello";             // литерал только для чтения
// s[0] = 'H';                       // UB
char buf[] = "hello";                // копия, можно менять
buf[0] = 'H';                        // OK

// VLA (C99, опционально в C11)
void f(size_t n) {
    int vla[n];
    // ...
}
```
